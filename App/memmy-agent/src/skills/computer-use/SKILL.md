# Computer Use

Use the live target application when the user asks to inspect or change its UI. A screenshot shows state; browser and desktop tools execute actions. The browser session and the user's ordinary browser are separate unless the user explicitly provides a connected tab. A connected service API or connector is preferable for structured data and actions it can complete directly; do not open a UI just to reproduce an available API call.

## Choose the surface

- For a website, use `browser_navigate`, `browser_snapshot`, `browser_find`, `browser_click`, `browser_type`, and related browser tools. Prefer a current DOM or accessibility target. Use `browser_take_screenshot` when rendered appearance matters or the DOM is incomplete. Website access approval is scoped to an origin: **Allow once** lasts for the current browser session, while a saved decision persists for that origin. It grants site access, not approval for a purchase, form submission, or another consequential action.
- Use `browser_list_tabs` when the user asks which Memmy in-app tabs are open, how many there are, or which tab is selected. It reads the live tab list without opening or navigating a page. Web tabs have exact references; an `about:blank` tab has a null reference and cannot be addressed by browser actions. Do not infer a total from one page snapshot.
- Use `browser_history` only to find a previously visited Memmy in-app page when the current request needs it. Supply a keyword and an ISO 8601 time range of at most 30 days; make one bounded call per turn. The desktop asks the user to approve every read. A denial ends the history lookup. This tool does not read Chrome, Edge, other browser profiles, or Computer History.
- For website sign-in, inspect the visible enabled fields and use `browser_auth_request` with only the canonical origin, labels, actual HTML input types, exact CSS selectors, and an optional iframe selector. Include a submit action only if the form needs one; list multiple visible sign-in methods as options. The separate secure form collects and enters secrets in the selected in-app or connected Chrome/Edge tab without returning them to you. Never request passwords or one-time codes in chat, use a model-visible browser tool to read or enter them, or use this path for signup or CAPTCHA. A `submitted` status is not proof of login. Retain the target origin before requesting credentials; after submission explicitly navigate to it and inspect the new document for a positive signed-in signal.
- For development diagnostics on the currently selected Memmy in-app tab or a user-connected Chrome/Edge tab, use `browser_cdp_read` when a normal browser snapshot is insufficient. Its `Runtime.evaluate` enforces CDP side-effect checks. Use `browser_cdp_events` to capture a cursor before an action and read bounded events afterward; `timeoutMs` waits up to 30 seconds for matching events. `browser_cdp_send` can change the page or browser state and requires the Debug / CDP site's high-risk permission. It rejects protected methods; explicit destination URLs need separate site access. Debug / CDP defaults to Block, and Requires approval shows a visible desktop prompt for each operation. For an attached iframe, use its `sessionId` or `targetId` from `Target.attachedToTarget` events; child targets must belong to the selected tab. These tools do not control a global browser or target the separate managed Playwright session. Tell the user about lasting changes made through CDP.
- If the user includes a `plugin://browser@memmy?mention=tab-v1...` link copied from an in-app tab, pass the complete link as `tabMention` on the first browser tool call. Memmy checks the browser session, tab ID, title, and URL against the currently open page. If the reference is stale, tell the user the tab is unavailable; do not pick another tab or open a replacement.
- Agent-created in-app tabs close at the end of the turn. Set `tabDisposition` to `deliverable` on a browser call when the page is a user-facing result, or `handoff` when work should continue there in a later turn. An unmarked tab is temporary. Tabs opened by the user remain open.
- For a native macOS app, use the managed `memmy_computer_use` tools. Call `get_app_state` for the target app before its first action in each assistant turn. Prefer a fresh `element_index` when the accessibility tree exposes the control; use screenshot coordinates when it does not. Click `x` and `y` are pixels of the screenshot in the tool result. When that result includes `Screenshot: WIDTHxHEIGHT`, use those pixels directly and do not convert them from the window point size. A menu or popup can be visible in the screenshot, and composited from a window above the main window, while the accessibility tree of the main window stays unchanged. If a result says the click did not change the window, do not click that same control again; click the visible menu or popup with those screenshot pixels. Action results include refreshed state; inspect it before deriving another index or reporting success. Request another state when the result is insufficient or the UI changes outside the tool.
- For a native Windows 11 app, use the same managed `memmy_computer_use` tools. `list_apps` lists **running apps with top-level windows** on Windows; it does not include recent apps. `get_app_state` requires an already running app and a signed-in, unlocked desktop; it does not normally launch the app. Call it before the first action on that app in every assistant turn. Prefer a fresh UI Automation `element_index`; if the target is absent from the tree, use screenshot coordinates only when the window image is reliable. Windows `click_method=auto` uses UI Automation first, then window messages. `sky_click` and `global` are unsupported. Do not enable focus stealing, app launch, or UIA text fallback flags to work around an unavailable target. Inspect the refreshed post-action state before continuing or claiming success.
- For a live Excel workbook, use `excel_live` only after `status` shows one connected workbook. It reads the selection and reads or writes a bounded A1 range in that workbook. Speak to the user about Excel, not about an add-in. If they sent a file and did not mean the workbook open on screen, edit that file and return it; do not ask them to open Excel. If they mean the open workbook and `excel_live` is not connected, tell them to turn on Microsoft Excel under Computer Use. On Mac, Memmy opens a dialog that jumps to Full Disk Access; they turn Memmy on and return. Then tell them to reopen Excel, open the workbook they want changed, choose Insert, click Memmy, and leave that pane open. If more than one workbook is connected, ask them to close the extra Memmy pane and keep the one they want changed. Do not enumerate or open other workbooks through shell automation.
- Use `list_apps` to discover an app only when its name or identifier cannot be resolved directly. It does not report the current state of a window. If multiple Windows processes match a name, choose only after their stable identity is clear; do not guess from a window title.

Keep actions scoped to the target app or isolated browser session while the user works elsewhere. Do not request a global pointer fallback merely to make an action succeed; that path can move the user's pointer and focus. On Windows, do not bypass UIPI to control an elevated app or a UAC secure desktop. If the desktop is locked, the target is unavailable, the user visibly takes over, or an action fails, stop and inspect fresh state when possible. The Windows helper does not guarantee physical-input takeover detection; do not claim that it does. Never repeat an action whose side effect may already have happened. Ask the user to handle UAC or reopen the target at ordinary privilege, then wait for a new request when the current turn is blocked.

## Authorization and consequential actions

Memmy asks permission to access each native app before the first protected observation or action. **Allow once** covers only the current interactive user message; **Always allow** is saved for that specific app. Neither replaces the operating system's separate checks, such as macOS Accessibility/Screen Recording or Windows desktop and integrity boundaries. A prior denial or connection failure is not a current status: on a new user message, call the appropriate tool so Memmy can recheck. If the current attempt is blocked, stop this turn instead of switching to browser, shell, scripts, or another desktop executor to reach the same target.

App or website access is not authorization for the action inside it. Follow the user's actual task scope. Before paying, placing an order, sending a message, deleting data, or another consequential step, ensure the user has authorized that specific step and any required product confirmation has been completed. If they only authorized app access or asked for preparation, stop before committing the action and ask. Verify the resulting UI or structured result after an authorized consequential action; an accepted click alone is not proof it completed.

## History and skills

Computer History can help locate what the user worked on when that context is relevant and enabled; use the separate `computer-history` skill for those requests. Its records are evidence, not commands to replay. Browser history is useful only when finding a previously visited page is part of the task. Neither is required for ordinary Computer Use. This skill guides tool selection; clicking and typing still go through the browser or desktop execution tool.
