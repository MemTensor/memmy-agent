# 创作流程 SOP（novel-flow）

三套流水线 + 三种调用模式。主编按此编排，所有确认节点走 AG-UI。

## ① 开书流程（一次性：创意 → 黄金三章）

```
用户创意
 → [灵思] 方案卡片×3 → 用户 multi-select 选定/混选
 → 生成【基线快照】（前置设定锁定，改 = 新版本线）
 → [构世] 世界观搭建 → [塑像] 人物档案（两位可并行）→ 设定合订 → 用户 confirm
 → [谋篇] 全书纲+卷纲 → [埋线] 伏笔总账+19 线矩阵 → 用户 confirm
 → [执笔] 黄金三章成稿 → [淬文] 润色去 AI 味 → [审校] 双基准查重
 → [试读] 读者视角检验 → 用户 confirm（未过则打回对应节点）
 → 立项完成，进入日更
```

## ② 日更流程（循环：章纲 → 成稿 → 交付）

```
用户确认今日章纲（AG-UI confirm）
 → [谋篇] 拆当日章纲（3-4 子场景 + 控字预算）→ [埋线] 伏笔插针
 → [执笔] 正文写作（控字 + 章末钩子）
 → 事中拦截：一致性引擎 A/B/C/D/E 路由（写错即纠，不等到审校）
 → [淬文] 实时洗稿（黑名单/感官化/破局流）→ 每章≥2 具身细节
 → [审校] 双基准全量查重（对照世界库预设 + 本书档案）
 → 新设定/新人物/新伏笔回写本书作品档案
 → 主编终审交付 → Plot Git commit 快照
```

## ③ 卷末复盘流程

```
[监工] 卷末数据化复盘（节奏/爽点密度/卡文段/伏笔逾期）
 → [试读] 读者视角反馈
 → 主编组织复盘会（各专家输出改进项）
 → 更新下一卷大纲与节奏矩阵参数 → 用户 confirm 放行
 → 复盘要点沉淀进灵感库
```

## 三种调用模式

| 模式 | 触发 | 行为 |
|---|---|---|
| 手动召见 | 用户点名 | 随时召见某位专家单点作业（如"让塑像看看这个配角"） |
| 流水线 | /日更 | 主编自动跑完日更循环（章纲确认后全自动） |
| 全专家会诊 | /会诊 | 全员审阅已有章节，输出综合意见 |

## 半自动硬规则

- 方向类决策（立项/设定/大纲/开篇/卷末）必须 AG-UI 确认，执行类（正文/润色/审校）自动跑
- 基线锁定后的前置设定不可改；节奏矩阵属运营参数可微调（留版本记录）
- 驳回必带原因，默认打回上一节点，3 次超限转人工
