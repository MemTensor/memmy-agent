## 2026 年 10 月 16 日采集器方向调整

当前采集器以通用能力优先：默认尝试读取前台窗口，应用专属信息用于改善定位和元数据。浏览器普通、无痕和模式未知均可采集，URL 未知也保留内容；明确密码、敏感控件、凭据脱敏及用户应用排除继续生效。共享设置的 macOS 默认行为不变。

已落地：浏览器不再被家族黑名单拒绝，正文规则不再自动关闭通用读取；通用路径按 TextPattern、ValuePattern 与 LegacyIAccessible 能力读取任意控件角色；兼容窗口子树内不同 PID；缺少 Name、正文与 Name 相同或 TextPattern 失败时不再整段清除；焦点分支优先、可见范围先于文档上下文，Control View 无正文时尝试 Raw View，并发出窗口级 Chromium 辅助功能请求。C++、TypeScript 及摘要来源同步调整。

显式 `captureText:false` 保留为旧受限配置兼容模式，默认配置和区域提示均不会进入该模式。窗口身份、前后台检查、worker 隔离、超时和增量结构校验继续保留。跨进程范围按当前窗口子树定义，允许其中的托管内容；它不等同于扫描所有后台应用。

本轮范围为采集器修改、构建和定向回归。下面的 10 月 15 日计划与里程碑为原阶段记录，涉及普通浏览器模式证明和专属正文准入的旧要求由本节替代。最新结果见 [验证记录](VALIDATION.md)。


本阶段交付统一的采集规则和管理入口，补齐普通文本与 Electron 应用的通用采集能力。产品行为以当前 macOS 实现为基准；Windows 保留必要的系统适配，并继续使用现有 C++ 采集器、共享录制、摘要和检索链路。

目标是让常用软件在开启采集后获得有意义的历史内容，并减少用户配置和逐个应用适配的成本。阶段完成以核心场景可用为准，兼容性限制必须明确报告。

## 已确定的设计边界

1. **统一框架，少量内容读取模块。** 窗口识别、调度、过滤、去重、预算、存储和摘要共用。UIA 按控件实际提供的能力读取内容；浏览器保留专用上下文校验。Electron 的处理集中在辅助功能接入和必要的正文定位。
2. **以 macOS 的规则语义为基准。** 应用和网站分别有默认行为，排除规则优先；页面与 Agent 使用同一份有效配置。Windows 的进程绑定和内部预算不转化为逐 App 用户授权。
3. **普通编辑内容进入通用能力。** 非密码正文和控件值按通用规则读取；继续执行密码过滤、凭据脱敏、隐私窗口排除和现有独立数据源授权。扩大正文能力与修改用户应用范围是两件事，旧范围迁移不能扩大授权。
4. **内容来源明确。** 分别表达控件当前值、provider 报告的可见文本、文档上下文。完整 DocumentRange 不自动成为屏幕可见证据，也不证明用户读过或输入过全文。
5. **先使用能力，再保留例外。** 现有 Word 和 VSCode 规则作为兼容补充；通用路径通过回归后再收缩。新增应用例外必须有通用路径失败的证据和稳定的识别依据，不按窗口标题、坐标或每个页面增加业务模板。
6. **控制工程规模。** 使用小型读取接口和静态路由，不建立动态插件市场、通用抓取脚本系统或每 App 独立录制管线。原生与 TypeScript 的独立校验保留，但共享协议和规则样例，防止两端语义漂移。

- [x] 明确旧别名与精确应用规则的匹配：适用的排除规则优先；新精确允许规则不能绕过仍有效的旧排除规则。辅助进程的匹配不能直接套用 macOS bundle ID 后缀规则。
