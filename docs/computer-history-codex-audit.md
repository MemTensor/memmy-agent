# Codex Computer History 解包核查（2026-09-27）

核查对象是本机安装的 ChatGPT/Codex 桌面版 `26.924.22138` 和其独立的
Computer Use 服务 `26.923.1001242`。本报告只记行为、接口和架构证据；没有复制
应用程序代码，也没有读取个人历史事件、设置或记忆文件。

## 核心结论

**可以借鉴并独立实现功能，但单靠解开 Electron 包无法完整复刻。** `app.asar`
能看到 History 的设置、列表展示、控制桥接和部分状态约定。真正的事件采集在独立的
macOS 原生服务中；十分钟、六小时摘要及长期记忆整合还有模型处理环节。这里的
“源码”特指打包前的 Electron 与原生工程文件及未下发的服务端实现。Memmy 可以
用自己的云服务和模型实现对应流程，无须取得 Codex 相同的模型输出。

## 本机证据

- `/Applications/ChatGPT.app/Contents/Resources/app.asar`：History 前端组件、
  应用发现及设置查询。设置有应用和网站两条独立的允许／排除轴，支持查找应用和添加域名。
- 捆绑的 `computer-history` 插件启动器实际调用
  `~/.codex/computer-use/Codex Computer Use.app` 内的
  `SkyComputerUseClient`；同一应用中的 `SkyComputerUseService` 执行原生采集。
- 原生服务的公开符号和资源可确认事件 tap、AX 通知观察、按窗口缓存 URL、键盘文本
  缓冲、终端内容变更缓冲、分段写入以及十分钟／六小时摘要流程。符号只能证明存在这些
  组件，不能证明每种浏览器和应用的实际覆盖率。
- 独立资源描述了十分钟、六小时摘要、工作流建议和后续记忆整合。官方
  [Computer History 说明](https://learn.chatgpt.com/docs/customization/computer-history)
  进一步确认原始事件本地保留最多 48 小时，摘要通过临时 Codex 会话生成。
- [Computer Use 说明](https://learn.chatgpt.com/docs/computer-use) 将应用控制及其授权
  列为另一项能力。History 的采集范围不能直接当作 Computer Use 的控制权限。

## 与 Memmy 的差距及处理

以下对照是解包时的基线判断；本次实现后的状态见文末更新。

| 方面 | 现状与证据 | 本轮处理／后续工作 |
| --- | --- | --- |
| 采集范围 | Memmy 已有应用、网站规则和后端工具，但桌面 History 页面只有录制总开关 | 本轮增加应用目录、双轴默认策略及单条规则的桌面设置入口，并通过同一规则引擎保存。 |
| 浏览器隐私 | Memmy 只向 Chrome、Arc 查询私密状态；Safari 私密窗口会被记录；Apple Events 查询失败也按非私密处理 | **未达到 Codex 产品声称的排除效果。** 需要逐浏览器实测可靠的私密窗口信号，并设计查询失败时的安全行为。不能仅根据二进制符号断言 Codex 也覆盖所有浏览器。 |
| 事件完整度 | Memmy 已有事件 tap 与 AX 快照，但 `kAXValueChanged` 没有真正采集内容，也没有按窗口 URL 和终端变更缓冲 | 下一阶段应优先补 AX 内容变化与 URL 上下文，随后用编辑器、终端和多窗口浏览器场景衡量丢失率。 |
| 进程生命周期 | Memmy 录制器是 agent 的子进程；Codex 使用独立原生服务和控制客户端 | 先量化 agent 重启和睡眠唤醒时的断录，再决定是否迁移到常驻服务。 |
| 摘要与记忆 | Memmy 已有十分钟、六小时摘要与工作流抽取；Codex 还有后续长期记忆整合 | 先改采集证据覆盖与摘要安全边界，再考虑长期记忆层；模型输出无法逐字复刻。 |
| 电脑控制 | Memmy 有 Open Computer Use 工具；Codex 的 Computer Use 是独立的应用授权能力 | 单独梳理可控应用、授权、操作回执及撤销；不要与 History 采集许可混用。 |

## 本轮代码改动与验证

- History 页面增加“采集范围”：搜索已安装应用、按 Bundle ID 添加应用、按域名添加网站，
  切换包含／排除模式及每条规则的行为。只在展开面板时读取应用目录。
- Agent 新增经认证的设置读写与应用目录接口；复用现有 macOS 图标辅助程序做目录发现。
  策略文件改为先写临时文件再原子替换，避免录制器读到半份 JSON。
- Swift 辅助程序在本机编译并输出应用目录；agent、桌面端 TypeScript 检查通过；
  后端相关测试 51 个、桌面 History 交互测试 43 个通过。

## 复刻边界

目前不能声称“完全复刻”：原生采集器的具体过滤逻辑、不同浏览器的私密状态识别、
模型摘要和长期记忆生成规则仍有未证实部分。建议以用户可观察的功能验收为目标，
建立真实应用矩阵，分别测试采集、排除、摘要和控制权限。

基于 9 月 24 日 `v1.1.9` 记忆服务改动的接入设计见
[Computer History 与 Memory 服务接入方案](computer-history-memory-integration-v1.1.9.md)。

## 2026-09-27 实现更新

- macOS 录制器现在把焦点控件的 AX 值变化纳入观察；浏览器私密状态无法验证时整窗排除，不再把查询失败当作普通窗口。Chrome 系、Safari 与 Firefox 的实际覆盖率仍需逐个版本实测。
- 桌面 History 已有应用与网站的双轴来源设置、按已安装应用搜索、默认策略与单条规则；设置在 agent 侧落盘并由采集器逐事件执行。
- Windows 11（build 22000 起）新增前台窗口与 UI Automation 控件树采集，复用本地分段、摘要、来源策略及时间线。Windows 版暂不采集浏览器内容，因为尚无可靠的逐窗口私密状态判断；没有真实 Windows 主机的端到端测试，不能声称与 macOS 同等覆盖。
- 录制开关现在把已明确选择的运行、暂停、停止状态保存到本机。agent 重启后仅对先前运行中的录制重新检查系统权限和来源设置后恢复；暂停状态仍保持暂停，主动停止会撤销恢复意图。
- 个人微信来源已合入独立授权门控：未授权时一般观察器跳过微信窗口，授权后才允许相应事件及聊天来源进入 History。该门控与应用范围规则共同生效，仍需真实微信环境验收撤权和内容边界。
- 可选 Memory 适配器把完成的十分钟摘要及关闭的六小时汇总同步为独立的 `observed_activity` L1 观察证据，具备幂等版本、检索、来源关联和删除 tombstone；History 可以直接打开对应的记忆详情。它不伪造 agent 对话。
- 多段已同步 History 如果有足够的语义操作证据，会经 Memory 的模型检查生成待审阅的 Skill 候选。候选在 Memory Skill 列表可见，审阅前不能召回或使用；History 内的统一入口把同一 Skill 所依赖的多个记录合并展示。Windows 11 应用目录现在还包括开始菜单里的 Win32 快捷方式。真实机器覆盖率和签名安装包验收仍未完成。

## 2026-09-28 开启流程与展示核查

- `chronicle-permissions-dialog` 的自定义范围界面有并列的应用、网站面板，两个轴分别支持“排除这些”与“仅包含这些”策略。Memmy 现在把同样的选择放在开启确认之后，用户点击继续时才保存规则；取消不改变已保存设置。关闭态页面复用上新介绍卡；开启后的设置页用“权限 → 选择”重新打开同一选择器，移除了重复的内嵌规则编辑器。
- Codex 在未启用 Memories 时另有启用确认。Memmy 的记忆服务默认可用，因此没有复制这一步；新安装的 History 设置默认把完成的摘要同步到记忆服务，已有的明确关闭设置保持关闭。未开启 History 的用户没有采集内容，独立安装的记忆服务不依赖 History。
- 开启后的页面改成居中窄栏、较大的标题、分组设置卡片和独立历史列表；记忆同步作为独立设置行，保留 Memmy 特有的微信授权、记忆同步状态、来源记忆以及 Skill 快捷入口。
- Codex 的“在菜单栏中显示指示器”操作的是专门的 History 录制点。Memmy 通过全局应用菜单栏图标旁的圆点显示录制状态，页面关闭后仍由应用级轮询轻量状态接口更新，不会每次读取完整 History；用户可在 History 设置页关闭该指示器。如果全局菜单栏图标被关闭，指示器也不可见。
- 已在本地生成 Windows x64 未签名 NSIS 安装包，检查打包内容和原生二进制架构，并把安装包传入 Windows 11 虚拟机核对 SHA-256。该虚拟机为 Windows 11 ARM，通过 x64 模拟运行，不能替代原生 x64 主机覆盖率。
- 虚拟机中运行安装包时出现 NSIS「Can't initialize plug-ins directory」，因此安装流程尚未通过。解压版能启动主进程并打开渲染窗口，但曾显示空白。进一步检查发现其中一次增量覆盖只替换了 `app.asar` 与 `Memmy.exe`，遗漏了包含前端资源的 `app.asar.unpacked`；浏览器验证该混合目录的脚本和样式请求返回 403。已重新备好完整一致的目录包，仍需在虚拟机里完成界面、采集和权限矩阵验收。不能据当前证据宣称 Windows 版可用。
