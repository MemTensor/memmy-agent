本地分支：`codex/v124-feature-migration`。

- 基线：主仓库 `upstream/main`，`74b26fc7`，项目版本 1.2.4。
- 来源：迁移前的本地 v1.2.5 快照 `codex/v125-source-snapshot-20261026`，`fc4cadd0`。快照包含当时的 66 个已跟踪修改和 10 个未跟踪文件。
- 原来的 v1.2.5 工作目录和法律插件仓库未修改；本分支未推送，现已按用户要求启动为本地桌面开发环境。

## 迁移范围

| 能力 | 实现 |
| --- | --- |
| 插件商店 | 目录、账号资格、安装、更新、启停卸载、运行时、MCP 桥接、私有技能与 Host 服务，以及构建时的旧插件迁移状态。 |
| 通用提问 | `ask_question`、回答与取消协议、问题和答案回放；在 1.2.4 原来的活动区内增加问题节点。失效请求在历史加载时结束等待。 |
| 法律插件卡片 | 指引、材料上传、提问、录音交互及回答记录；继续使用插件提供的交互协议。 |
| 文件交付 | Host 校验并公布候选路径，Agent 选择文件并通过 `message(media)` 交付。附件列表只收实际媒体附件；候选产物和 Markdown 引用不自动算作交付。 |
| 录音 | 独立录音页、插件录音卡、实时与最终转写、说话人分段、保存与重试、向材料卡移交。切换聊天时保留录音实例，并保留开始录音时的会话归属。 |
| 任务计划 | 会话级持久化任务清单、创建与更新工具、WebSocket 状态同步，以及嵌入原过程区的清单卡。 |

文件预览、音频上传、工作区文件接口、插件数据库迁移、构建依赖属于上述功能的依赖，也随本次迁移接入。

## 保留的边界

- 使用 1.2.4 的消息队列与目标机制；普通发送先入队；仅在用户点击“引导”且服务器接受后结束当时待回答的交互。未迁入队列排序。
- 使用 1.2.4 的过程分组、折叠、滚动和普通历史排序。`buildAgentDisplayUnits` 的分组算法保持原样，只增加卡片识别和渲染。
- 未迁入 1.2.5 的紧凑过程重组、文献专用阶段展示、流式输出缓冲和“附件发送成功后立即结束整轮”。
- 保留一次性的文件交付提醒；它让模型判断是否交付，不自动发送文件。
- 插件的运行结果与外层 Agent 状态分别处理，不把外层停止改写成插件失败。

## 卡片与工具的关联

Agent 将唯一的 UI 工具调用标识和轮次标识送入插件 MCP 元数据。Host 在 `plugin.capability_event` 中透传可选的 `agentToolCallId`、`turnId`。法律问答记录保存这个标识，直接挂到对应工具行；不按时间或文案猜测关联。

使用唯一 UI 调用标识可以区分模型重复使用同一个 Provider call ID 的情况。旧记录若缺少此标识，不强行匹配到新的工具行。

## 快捷入口接入修正

修复首次真机验证发现的入口问题：空白新任务页不再展示法律快捷按钮和重复的录音按钮。法律快捷按钮只在相关会话中出现，放在输入框附近；“访谈录音”及显式的 `/legal-record` 使用 Host 录音卡，不调用需要诊断会话的 `material-collect`，也不自动创建诊断会话。已完成录音不阻止打开下一次录音卡。迟到的接口错误按发起会话归属，不显示到另一会话。

新增 hook 集成测试覆盖空白页、普通会话、法律会话、本地录音入口、只读指引与跨会话错误隔离。相关 119 项测试和前端 TypeScript 检查通过；已确认当前服务提供更新后的代码，实际桌面新任务页已恢复正常。本次未重启仍在执行任务的后端。

## 交互卡片与输入框修正

等待回答的通用提问卡由输入区固定容器直接持有，不再跟随过程区折叠而消失；卡片显示在输入框上方，输入框保持可用，按卡片与队列的实际高度为消息区留出空间，新问题到达时滚动到卡片上方的等待提示。回答后，在原过程位置留下默认展开的问答记录，并去掉重复的提问工具行。保留普通过程的分组、历史顺序与用户手动滚动行为。

插件能力名不会再按尾部 `task` 误识别为子 Agent；例如 `review-create-task` 使用插件清单中的“创建综述任务”，真正的提问使用“向用户提问”。新任务和会话输入框恢复已知斜杠命令的高亮，仍使用原生 textarea 处理输入和提交。

补回文献卡片的公共边框样式，以及 FileTypeIcon 配套的共享样式和尺寸、颜色变量。后者也修复诊断指引的三列布局失效和上传列表文件图标不可见的问题，沿用迁移来源的原始样式。

卡片、历史、队列、滚动、高亮与插件相关 13 个测试文件通过：344 项通过、3 项跳过；前端 TypeScript 检查通过。用独立测试数据操作真实组件，验证待回答卡片、提交后的问答记录、文献卡边框、命令高亮、诊断指引布局和 Word/PDF/Excel 图标。没有代答用户正在运行的任务，也没有重启后端。

本次 UI 修复不改文件交付。迁移版仍由主流程选择最终文件并调用 `message(media)`，保留漏发时的一次提醒；正文不强制重复附件卡已有的链接列表，发送附件也不自动结束整轮。

## 用户快捷入口与 Agent 流程卡隔离

迁移初期安装的法律插件是 0.1.0，其 `/legal-guide` 仍绑定 `session-start`，没有 `guide-open`。用户要求删除旧快捷映射，不保留兼容分支：桌面快捷指引统一调用独立的 `guide-open`，Host 强制以只读卡展示。Agent 调用 `session-start` 的流程卡仍保留录音与上传选择。2026-10-26 用户要求重启后，本地 0.1.6 已启用，其 `/legal-guide` 指向 `guide-open`。

独立“访谈录音”继续使用 Host 录音入口，不调用 `material-collect`，也不发送继续诊断的消息。

## 运行中会话切换后消息缺失

文献综述会话的原始记录和后端回放仍包含首条用户消息，但前端在运行状态下优先保留局部缓存，完整历史未被合入。迁入 1.2.5 已有的 `mergeOpenTurnHistory` 及打开会话、后台补载两处接入：恢复历史前段，同时合并后到的实时文字和工具状态，不替换整体消息队列或运行器。

原版的会话切换回归用例与两个用户消息缺失用例在迁移前均失败，迁入后全部通过；相关 5 个测试文件 279 项通过、3 项跳过，前端 TypeScript 检查通过。

## 等待提问时的排队与引导

普通发送不再传递自动打断提问的标记，运行器也不再因为入队自动停止当前回合。只有用户明确点击队列的“引导”、服务器接受后，桌面才结束当时捕获的原生问题或 Agent 所属插件交互。模型在当前任务里继续处理引导内容；其他排队消息、独立录音、用户指引及之后新出现的问题不会被这次操作清掉。卡片关闭失败时保留卡片，并明确提示引导已提交但卡片未关闭。

排队卡使用 1.2.5 的样式、操作图标与附件预览，放在所有待操作卡片上方；保留 1.2.4 的队列协议与排序方式。原生提问卡不再遮住或禁用输入框，等待提示留在整个卡片和队列区域的上方。

前端相关 112 项测试通过；运行器排队与消费的 28 项既有测试通过，新增真实运行器测试通过，覆盖两条消息排队、选择第二条引导、结束当前问题后只消费第二条且保留第一条。前端和 Agent 类型检查通过。隔离组件页面验证普通发送仅入队、点击引导后收起卡片并显示引导消息。

用户最初要求等通知再升级插件和重启服务；2026-10-26 已收到重启指令并完成加载。运行器变化已由测试覆盖，真实会话中的提问与引导仍需用户继续验证。

## 文献插件过程行融合

`read_plugin_skill` 是 Host 的通用工具；文献综述的 `review_*` 是插件能力。两者继续使用 1.2.4 的同一过程行：14px / 24.5px 的工具文字、14px 图标、8px 图文间距、4px 步骤间距。插件进度只作为所属工具行的次级文字显示，匹配通用过程备注的 12.5px 字号，不额外生成文献阶段面板。

中文界面为当前文献插件的全部 30 个能力补充展示名称；英文界面继续使用插件清单名称。技能调用依 `pluginId` 显示“读取文献综述技能”，其它插件使用通用“读取插件技能”。工具参数与原始结果保留在既有的默认收起详情中。

活动中的最新工具组依旧自动展开，过去步骤自动折叠；用户手动设置的展开或折叠状态在后续步骤到达时保留。文献提问继续使用通用提问卡，最终附件继续走会话文件交付规则。相关 103 项过程与卡片检查及前端 TypeScript 检查通过。

## 任务计划与卡片过程双态
