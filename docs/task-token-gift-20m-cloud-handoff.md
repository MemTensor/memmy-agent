# 1.2.5 任务 Token 自动赠送：云端改造交接

最新产品口径：**至少 1.2.5，并且在这个版本上首次登录后自动发放，不需要点击领取。** 旧版本登录不发放。1.2.5 及以上进入工作区时调用 `ensure`，服务端只在这个接口里发放。老用户发放后看到账弹窗；新用户发放后不看到账弹窗。新功能介绍只展示到北京时间 **2026-11-20 23:59:59**，看的是打开 1.2.5 的时间，不是赠送截止日期。两种弹窗每个账号只出现一次。

## 发放规则

- 账号注册时间早于 1.2.5 上线的为**老用户**，之后为**新用户**。发放门槛是客户端版本至少 1.2.5，不是「只有 1.2.5 这一个版本号」。之后的版本第一次登录、当时还没发过的，仍然发放。
- **新用户**：在 1.2.5 及以上第一次登录时，基础任务 Token **总额定为 2000 万**。原来的 200 万基础额度换成这一档，不能加成 2200 万。保留已使用量；邀请、抽奖、改进计划、人工加额等独立奖励不应被覆盖。
- **老用户**：在 1.2.5 及以上第一次登录时，在原有任务额度上**增加 2000 万**。原使用量、其它奖励和额度规则保持不变。
- 使用固定 `grantId`：`v125_task_token_gift_20m`。额度账本对 `(account_id, grant_id)` 建唯一约束。资格检查、赠送登记和额度更新必须原子化。每个账号只发一次。打开弹窗和确认已读不能再次发额度。
- 不要把发放写进旧版也会调用的登录接口。1.2.5 及以上才会调用 `ensure`。11 月 20 日之后打开的老用户仍然发放。

## 桌面端已接入的云端接口

均沿用云账号 UUID 的 Bearer 鉴权。账号、分组和金额由服务端判断，不能从请求体信任这些值。两条路径的桌面本地代理已写好。

### `POST /api/agentUser/quota/launchGift/ensure`

请求体 `{}`。服务端幂等确保该账号已经获得本次赠送，并返回**尚未确认已读**的通知。首次发放/通知未读时：

```json
{
  "hasGift": true,
  "grantId": "v125_task_token_gift_20m",
  "audience": "existing",
  "tokenAmount": 20000000,
  "totalTokens": 22000000
}
```

`totalTokens` 是该账号真实的发放后任务额度；示例仅表示原有 200 万的老用户。新用户返回 `audience:"new"`，基础任务总额度为 2000 万。通知已读后返回 `{"hasGift":false,"audience":"existing"}` 或 `{"hasGift":false,"audience":"new"}`。已有赠送只需读账本，不能再次加额。请保留 `audience`。客户端用未读通知作为「这个账号还没看过这次弹窗」的标记：11 月 20 日 24:00 前，老用户把到账和四项新功能合成 5 页，新用户只看后 4 页；11 月 21 日 0 点起，老用户只看到账，新用户不弹并直接确认已读。完全不适用的账号可返回 `{"hasGift":false}`。

### `POST /api/agentUser/quota/launchGift/ack`

请求体：

```json
{"grantId":"v125_task_token_gift_20m"}
```

仅标记本账号的这条到账通知已读，返回布尔成功；**不改额度**。重复确认幂等。老用户关闭到账弹窗时调用；新用户关闭功能介绍，或在 11 月 21 日之后登录且没有任何页要展示时，也会调用，避免到账页以后再冒出来。异常退出而未确认的通知下次仍可看到。

## 现有配置同步

- 登录页黄条是「注册即送 {金额} Agent 任务体验 Token，开箱即用」。点进去后，卡片上的大数字是同一个金额，下面还有三句：可用于 Agent 对话和完整任务；可自动整理 5000+ 条历史对话为记忆；覆盖全功能。金额来自 `GET /api/memmy/desktop/promotions` 的 `agentChatTokenTotal`，改为 `20000000`。`loginBanner` 仍决定黄条出不出现。
- 点进去的副标题「另有 2,200 万记忆处理 Token，不计入任务额度」写在客户端里。这 2200 万是记忆处理额度，不要改成 2000 万，也不要并进任务 Token。
- 接口上线前，客户端调用 `ensure` 失败时会隐藏这次弹窗，不会误报“已到账”。本地 mock 仅演示界面，不会发真实额度。

## 必验场景

1. 新账号原 200 万基础额度：自动赠送后基础总额 2000 万；再次登录不增加。
2. 老账号原 200 万：自动赠送后总额 2200 万；再次登录不增加。
3. 老账号已有消耗或其它奖励：只增加本次 2000 万，历史消耗与奖励不变。
4. 两设备同时进入：赠送账本仅一笔，额度只加一次。
5. 已读/未读通知、多次查询与多次确认：不重复发额度。
6. 旧版本登录：不调用 `ensure`，额度不变，不弹窗。
7. 老用户第一次打开 1.2.5 及以上，且时间在 11 月 20 日 24:00 前：加 2000 万，客户端把赠送和新功能合成 5 页。关掉后不再弹。
8. 老用户第一次打开发生在 11 月 21 日 0 点后：仍然加 2000 万，只看到账弹窗。
9. 新用户第一次打开 1.2.5 及以上：基础总额 2000 万，不看到账页。截止前只看新功能；21 日 0 点后不弹任何页，客户端会直接 ack。
