# Computer History 本地人测清单（2026-09-27）

测试对象：`codex/memmy-release-integration`，基于 `v1.1.9`。安装包与实际验收结果以本轮集成报告为准；旧分支的 1.1.8 测试包不能证明本轮功能通过。
## macOS 桌面端

上线通知：在 `1.1.9` 发布序列首次进入已完成引导的工作区时展示一次，关闭或点击“去开启”后不再弹。验证账号与 BYOK 用户均可收到通知；“去开启”应进入 History 并打开原有的确认弹窗，取消确认后仍保持关闭，确认后继续原有权限引导。中秋活动弹窗应在此通知关闭后再出现。

1. 全新安装与升级安装各运行一次。检查首次启用、权限说明、启动／暂停／恢复／停止，以及 agent 重启、睡眠唤醒后的状态。
2. 设置一个允许应用、一个排除应用及一个排除网站；在编辑器、终端和多窗口浏览器切换。确认只保存允许的内容，应用目录与域名规则可修改，私密浏览窗口及权限查询失败的窗口不写入。
3. 让授权应用产生可见内容变更，确认十分钟摘要、六小时汇总、时间线、搜索、按范围删除和文件定位可用。检查摘要是否把网页或应用内的第三方文字误写成用户指令或偏好。
4. 分别检查 History 关闭、Memory 服务未安装／离线、两者都开启三种情况。开启同步后，已叙述的 History 应出现在记忆管理中，History 的“查看记忆”应打开对应详情；离线恢复后只补送一次，关闭同步或删除来源后记忆不可再检索。
   还要在记忆管理中直接删除一条 History 观察记忆，确认 History 的旧链接自动消失，相关六小时观察记忆和 Skill 被撤回；切换 Memory 用户时不能把旧账户的 History 上传给新用户，撤回未完成时页面应显示错误。
5. 用多段连贯的语义操作检查待审阅 Skill：History 的统一入口应只列出实际生成的 Skill；同一 Skill 可以显示多个 History 来源；点击应进入记忆里的 Skill 详情。审阅前不可召回或执行；撤销任一必要来源后关联与候选应失效。

## Windows 11

1. 用 **x64 Windows 11** 安装本地 NSIS 包，确认观察器脚本随包进入 `app.asar.unpacked`，首次启动、权限和进程恢复正常。现有 VMware 虚拟机为 ARM64，已通过脚本自检，但不能代替 x64 安装验收。
2. 检查运行中及开始菜单中的应用目录；在记事本、文件资源管理器和一个常用编辑器中验证窗口切换、中文 UIA 文本、十分钟摘要与来源排除规则。密码框内容不得出现在原始记录或摘要中。
3. 检查暂停／恢复、退出重启、睡眠唤醒、删除与 Memory 同步。浏览器内容目前因无法可靠判断逐窗口私密模式而停采，应在界面确认此覆盖边界符合预期。

个人微信独立授权已合入此本地分支。Mac ARM64 安装包应含 `app.asar.unpacked` 内的 SQLCipher、OpenSSL crypto 和两份许可证；在未装 Homebrew 的测试机上验证“连接微信”的引导、只采集授权后的新消息、撤销后 AX 与数据库读取同时停止，以及原应用恢复。当前合成 SQLCipher 数据库与打包暂存库已在本机通过，只代表库可加载和读取，不代表签名安装包或真实聊天验收。
