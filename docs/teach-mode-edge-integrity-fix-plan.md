# Teach Mode 浏览器录制完整性修复方案

状态：修复已落地，Windows 验收通过；Mac 实机验收待完成，尚未发布。日期：2026-10-22。

实施补充：实机证明页面关闭回调中的 CDP binding 消息仍可能丢失，因此经用户再次明确授权，页面事件改走扩展原生内容脚本 Port。
扩展升级为 1.2.0，内部协议为 `teachingCapture/v2`；清单增加普通 HTTP(S) 主文档匹配，安装时需确认网站访问权限。
实际采集器仍在教学窗口身份与政策校验后启用，Host 再次校验。
Bing 的极短自动跳转页只有收到已绑定 Port 的“零次受支持操作”关闭证明，才能排除采集缺口；缺少证明或发生过操作时保持 partial。
下文保留原审核稿，CDP uniqueContextId/binding 路径已由上述原生 Port 方案替代。

验收结果：相关自动回归 170 项通过；Windows 交互桌面上 Chrome、Edge 各 10 轮 × 100 次导航，逐条核对共 12,020 条事件；20 个生命周期、故障与隔离场景通过，包括实际点击浏览器调试提示取消。
Memmy Dev 对话中的安装、录制、提取技能、执行第 2–5 条、停用及卸载均已尝试并留存证据。
Edge 新会话为 28 条 available，Chrome 为 29 条 available；四条输出均与当次网页核对。
Chrome 回放首次未落盘，补充定位和输出路径后继续完成，不计为零干预回放。
完整结果与限制见 验收记录（本地归档 `verification/edge-integrity-fix-2026-10-22/verification.json`） 和同目录 PDF；旧 partial 录制保持原状。

建议沿用现有扩展与 Host 通道，增加逐文档的事件交接协议，并把“本次停止是否确认”与“历史采集是否有缺口”分别记录。先完成状态与诊断修正，再实现页面交接，最后用原业务流程验收。

本方案依据真实 Windows Edge 复现及当前源码。修复范围覆盖 Chrome、Edge 共用的浏览器录制链路。浏览器教学窗口、日常登录态复用、对话内控制及 Record and Replay → Skill Creator 的产品流程沿用现有设计。

## 1. 已确认的问题

| 问题 | 当前行为 | 影响 |
| --- | --- | --- |
| 页面跳转撞上确认请求 | checkpoint 取到旧执行上下文，发出命令后页面销毁，CDP 返回 `Cannot find context with specified id` | 扩展产生 `browser_capture_document_fence_failed` |
| 历史缺口与当前边界混用 | 会话 issues 永久保留，后续 ack.complete 一直为 false；Host 据此判断当前边界未确认 | 最后停止与序号对齐，仍出现完成未确认提示 |
| Host 只保留标签页最新文档 | 新文档覆盖旧身份，导航中的旧文档尾部事件无法按独立文档核对 | 只修扩展仍不足以证明跨页面事件完整 |
| 故障证据不足 | 片段只保留汇总错误码，缺少失败文档、确认请求及原始 CDP 错误 | 无法从上次业务录制反查首次触发的具体页面 |

受控 Edge 复现中，旧上下文确认请求发出约 2 毫秒后发生上下文清理，约 14 毫秒后收到上述 CDP 错误；后续停止序号一致，但会话仍为 partial。同场景 Chrome 本次通过，说明验收必须覆盖竞争时序，不能仅执行一遍正常流程。

原始 Edge 业务录制的 29 条事件、哈希、范围隔离和笔记保存均通过核对，但缺少逐请求诊断，因此不能断言原始那次在哪个页面触发，也不能据已有事件数宣称没有遗漏。

证据：定位结果（本地归档 `verification/edge-integrity-2026-10-22/diagnosis.json`）、Edge 诊断日志（本地归档 `verification/edge-integrity-2026-10-22/edge-navigation-1792639269704/extension-trace.json`）、原业务验证（本地归档 `verification/windows-teach-publications-2026-10-22/verification.json`）。

## 2. 完整性的判定规则

拟分别记录三项事实：

- `coverageComplete`：本次录制声明的采集范围内，是否还存在未解决的事件缺口。
- `boundaryConfirmed`：本次确认覆盖的事件序号是否已经收齐，并完成 Host 来源文件落盘。
- `snapshotSaved`：最终片段、证据哈希和会话状态是否成功保存。

这里的完整仅针对已声明支持的普通网页主文档操作，不扩大到浏览器菜单、系统对话框或尚未支持的页面内容。

| 最终结果 | 对话提示 | 片段状态 |
| --- | --- | --- |
| 三项均通过，且有事件 | 录制已结束并保存 | available |
| 三项均通过，但没有事件 | 录制已结束，未采集到可用事件 | empty |
| 停止边界和保存通过，历史仍有缺口 | 已结束并保存，部分网页操作未能确认完整 | partial |
| 已保存收到的事件，最终边界未确认 | 已保留已收到的事件，结束确认未完成 | partial |
| 文件写入、校验或最终保存失败 | 保存失败，并说明实际原因 | failed，保留能够恢复的部分证据 |

正在等待导航交接的请求先记为 pending；有证据完成交接后解除等待。只有已确认无法补齐的覆盖缺口进入持久记录。真实缺口会保留，不因后续停止成功或用户补充说明而自动消失。

Host 内部已有 `CaptureCheckpoint.boundaryConfirmed`，拟复用其语义。增加的浏览器协议字段与会话完整性摘要采用明确的版本和类型校验，不通过缺省值推断成功。

## 3. 按文档完成页面交接

### 3.1 保留文档身份和事件序号

扩展为每个主文档保留独立记录：所属会话与标签页、执行上下文唯一身份、本次启用代次、采集状态、已发送及已确认的事件序号。页面自己填写的窗口身份不作为授权依据。

CDP 命令优先使用 `uniqueContextId`，并进行能力验证，防止跨进程复用数字 contextId 后执行到错误页面。它解决身份指向问题；旧上下文销毁后的事件交接仍由下面的协议处理。[CDP Runtime 协议定义](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/json/js_protocol.json)

每个文档的事件有递增本地序号。关闭标记携带该文档的最终事件序号；扩展和 Host 均检查序号连续性。全局会话序号继续核对扩展到 Host 的消息传输，两个层次分别验证。

Host 从“每个标签页一个最新文档”调整为“当前文档 + 有限期保留的交接文档”。旧文档只允许排空原授权期间的尾部事件，完成交接后封存；不能借此读取旧页面、接收无限迟到事件或恢复已撤销的权限。

### 3.2 导航时主动交接

正常跨页拟按以下顺序处理：

1. 采集器在 `pagehide`／`freeze` 时停止该次启用的内容采集，通过原有 binding 发送关闭标记，包含最终事件序号。
2. 扩展把旧文档标为交接中，等待其尾部事件及关闭标记处理完成。新文档单独建立身份、核对范围并确认采集器就绪。
3. 若旧 checkpoint 返回上下文已销毁，核对它是否属于已识别的文档切换，以及旧文档的关闭标记、最终序号是否齐全。
4. 证据齐全时，用旧文档已完成的交接满足该文档的确认要求；证据不足时，保留具体缺口。新文档恢复录制只能证明后续采集恢复。

生命周期回调并非保证执行的可靠落盘机制。`pagehide`／`freeze` 标记只有在扩展和 Host 实际收到、校验并处理后才构成证据；浏览器崩溃、丢弃页面或缺失标记时，不能推断旧文档已经完整关闭。[Chrome 页面生命周期说明](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)

从前进后退缓存恢复时，建立新的采集启用代次，并重新验证当前会话、窗口及租约。停止、断连或插件停用之后，缓存页面恢复也不能重新开始录制。SPA 路由变化沿用同一文档，单独记录导航事件。[浏览器文档与导航身份说明](https://developer.chrome.com/docs/extensions/reference/api/webNavigation#concepts_and_usage)

采集器安装与启用时间也需要记录。新页面过早操作、采集器未就绪或失效期间可能产生的遗漏，不能靠新页面的结束回执掩盖，也不能通过补读整个输入框恢复。

### 3.3 分开事件处理和回执等待

文档创建、销毁、页面事件及关闭标记进入有序处理队列；checkpoint 协调器在队列外等待回执。处理队列不能阻塞在一个需要由自身处理的回执上。

拟区分确认请求结果：已确认、文档切换中、交接已确认、超时、采集器缺失、调试连接断开。上下文消失先进入导航交接核对；只有证据成立才能转为已确认。重试只针对仍有效的文档，不能重新调用已经销毁的 context。

建议初始时限：普通确认 2 秒，正常停止采用全局 5 秒期限，同一有效文档至多重试一次，重试计入总期限。各文档并行发出确认，事件按序处理，不能按标签页数量逐个累加等待时间。时限需用实机数据验证。

## 4. 停止、保存与诊断

1. Host 接受停止时固定截止时间和 stopId；重复请求沿用同一边界。
2. 扩展收到停止请求后关闭新文档的采集启用和租约续期，对正在采集的文档执行“停止内容采集 → 发送最终序号与标记”。已经交接完成的文档使用已保存的证明。
3. 排空截止时间内、原授权范围内的待处理事件，核对文档序号与会话序号。超时或证据缺失时保留缺口，停止流程仍需有界结束。
4. Host 对来源文件落盘，固定片段并落盘，计算哈希，保存最终状态。只有对应步骤成功，才填写相应的确认状态。
5. 撤销本次采集授权，清理监听器及录制标识。短期缓存最终停止回执，使重复停止不重开会话；取消、停用和断连继续立即撤销权限。

正常停止期间到达的新导航不允许重新启用采集。已经撤销的会话、移出教学窗口的标签页及重连后的旧请求，不使用导航重试机制恢复权限。

拟增加单独的 `capture-proof.jsonl`，记录文档交接、确认请求和错误；最终摘要保留在 session.json，证明文件也计算哈希。诊断内容限定为会话/文档/标签页身份、事件水位、状态、耗时、错误类别与经过过滤的 CDP 错误；控制标记不计入用户操作事件数，不增加页面正文或输入值采集。

对话中展示用户能够理解的原因，例如“页面切换期间有一段操作未能确认完整”。Skill Creator 继续由用户另行唤起；partial 片段先核对缺口，用户补充的步骤沿用单独确认机制，并保留原录制限制。

## 6. 实施顺序

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| A：修正判定与诊断 | 分别记录当前边界、历史覆盖和保存状态；补充故障证据；把已有竞态做成确定性测试 | 历史缺口仍为 partial，最终停止成功能被正确表达；真实丢事件用例不能变绿。此阶段单独不视为根因修复完成 |
| B：实现文档交接 | 新协议、文档状态、尾部序号、Host 交接记录及有界停止 | 正常导航不再因旧 context 消失而误判；缺失尾部标记或事件时保留缺口 |
| C：实机验收与配套发布验证 | Chrome/Edge 回归、原业务流程、证据文件和截图 | 满足下面验收标准，报告中明确区分已验证平台与未验证平台 |

页面关闭标记能否在实际 CDP 交接顺序中稳定收到，需要在 B 阶段首先验证。若普通导航仍无法获得可核验的尾部边界，应保留 partial 并补充设计评审；不能仅降低校验要求完成验收。

## 7. 验收标准

| 场景 | 必须验证的结果 |
| --- | --- |
| 精确重现旧 context 被销毁的竞争 | 旧关闭标记及序号齐全时通过；故意丢弃关闭标记或最后一个事件时必须 partial |
| 新页面已建立、旧事件迟到 | 在原授权范围内正确排空，事件顺序与身份正确，无重复；过期或不属于该授权的事件拒收 |
| 历史缺口 + 最终停止成功 | coverage 为 partial，最终 boundary 为 confirmed，提示不再误称当前保存失败 |
| 刷新、跨站、多重重定向、SPA、前进后退及缓存恢复 | 文档归属正确，采集启用代次不串用；导航取消后页面能正确继续 |
| 停止与导航/弹窗/租约过期同时发生 | 停止在全局期限内完成；无法确认时保留 partial；后续操作不进入片段 |
| 断连、浏览器重启、崩溃、插件停用、标签页拖出/拖入 | 沿用授权与撤销规则，重连不自动恢复旧会话 |
| 日常窗口、其他资料、无痕窗口、敏感字段 | 内容不进入本次证据；新旧文档交接不扩大范围 |
| 延迟回执、重复回执、伪造身份、序号缺失、落盘失败 | 校验能够拒绝；不会误报 available；保留对应诊断 |

自动测试需要能注入“命令发出后销毁上下文”“新文档先到”“尾部事件先后变化”等顺序；当前对任意 contextId 自动回成功 fence 的测试替身需要替换为有真实文档生命周期的替身。

Windows Chrome、Edge 各执行至少 10 轮、每轮 100 次受控导航，覆盖不同轮询相位；测试端保存预期操作清单，逐条核对事件身份、顺序、重复与遗漏。完整性以预期操作核对为准，不只检查没有错误码。故障注入的预期结果单独统计，不能混入正常用例的成功率。

最后重新执行用户原流程：在 Memmy 对话安装插件 → 进入 Teach → 搜索许志钦 → 记录 publication 第一条 → 提取 skill → 按 skill 记录第 2–5 条。Chrome、Edge 分别输出录制证据、生成技能、执行结果与截图；不能只验证事件条数。

Mac 使用同一套浏览器代码，但仍需在 Mac 实机验证 Chrome、Edge 的文档切换、缓存恢复、停止和隔离；在完成前标为未验收。

本审核稿拟采用的主要决策是：保留现有浏览器通道；引入逐文档交接；真实缺口继续保留；历史覆盖与当前边界分别呈现；修复后以原始完整业务流程作为最终验收。

历史实机证据保留在验收工作区的本地归档中；本次分支交付源码与同步结果，不包含这些历史截图及原始录制文件。
