# 1.2.4-rc.2 浏览器与 History 回归

## 本次变化

- 内置浏览器、Chrome、Edge 的普通网页操作共用 Playwright 执行层：定位控件、等待可操作、执行动作、返回当前页面状态。保留已有登录态、任务标签页管理、文件审批和登录信息保护。
- CDP 审批新增「始终允许此网站」，保存当前协议、域名和端口的 Debug / CDP 权限；可在现有网站权限设置中撤销。文件上传和下载的权限独立。
- 安装 Chrome / Edge 插件后，网页控件和操作前后变化可进入统一 History。没有 Agent 任务时也能记录，沿用 History 的记录开关、暂停、排除应用和网站设置。
- 网页记录区分操作尝试、已观察到的变化和新页面上下文。整页跳转未确认的结果不会写成成功；部分极快卸载仍可能来不及交付前态，需实测真实示范流程。
- History 的微信区域下面新增可展开的「网页历史记录增强」，与 Computer Use 复用同一个插件、安装流程和连接状态。首次未开启 History 时也提供入口。这里没有新开关。
- 插件版本为 1.0.5。网页记录采用隔离的内容脚本，不保持调试连接。浏览器的系统调试提示文案由 Chrome / Edge 控制，Memmy 无法把它改为「Memmy 操作中」。
- 保留 1.2.4-rc.1 的 Mac PiP 屏幕录制权限修复。

## 安装与升级

Mac 包为 arm64 中国版签名 DMG；Windows 包为 x64 中国版无签名安装程序。Windows 11 ARM 虚拟机使用 x64 兼容运行方式，需要在该虚拟机实测。

覆盖升级后先确认版本、登录、已有聊天和 History 数据仍在。已有插件复用同一安装目录和身份，浏览器可能要求确认新增的网页读取权限。检查插件版本为 1.0.5，再做下面的网页回归。

## 建议优先回归

| 功能 | 操作 | 通过标准 |
| --- | --- | --- |
| 两处插件入口 | 在 History 展开安装一个浏览器插件，再进入 Computer Use；也反向操作一次 | 同一插件、同一安装交互，连接状态一致；收起区域不启动录制 |
| 现有登录态 | 让 Agent 使用已登录的 Chrome / Edge 页面；在内置浏览器复查已有登录 | 继续使用原标签页和登录态 |
| 普通控件 | 在三种浏览器分别试输入、下拉、勾选、弹窗、页面加载后的点击 | 可操作并报告实际输入值、选中状态和结果；不会把点击确认当任务成功 |
| 动态页面 | 页面滚动、控件重建、弹窗变化后继续操作 | 能重新定位；失效目标给出重新观察要求，不点错其它控件 |
| 多任务 | 两个任务使用不同标签页；一个任务尝试使用另一活动任务的标签页 | 不串页；活动任务占用提示清楚；结束后可继续使用 |
| 用户接管与停止 | Agent 操作期间用户接管；关闭外部浏览器调试提示，再明确重新连接 | 操作停下，恢复符合现有流程；停止后不会悄悄重新执行旧动作 |
| 文件与登录保护 | 上传、下载各一次；使用现有安全登录交互 | 原有审批和保存位置有效；密码、验证码不出现在网页 History 内容中 |
| 持久 CDP 授权 | 选择始终允许，重复同站点操作并重启 Memmy；随后撤销权限 | 同站点沿用授权；其它站点和端口独立；撤销生效 |
| 手动网页示范 | 开启统一 History，无 Agent 运行，手动输入、勾选、选择，再查看该时间段记录 | 操作及状态变化进入同一 History；不会因为记录而常驻调试连接 |
| 记录边界 | 暂停或关闭 History，操作被排除的网站及私密窗口 | 新通道遵守记录设置和排除规则 |
| 原有 History | 原有桌面记录、微信、摘要、Memory / Skill 关联 | 原有流程继续可用；网页动作可作为有来源的经验材料 |
| 原有 Computer Use | Mac PiP、Windows 普通桌面操作各选一个原有成功任务 | 浏览器改动未破坏原有桌面流程 |

## 原来的两个 Windows 用例

重跑开票准备、查询并勾选发票两个任务，保留任务记录和失败位置。比较是否完成、总耗时、重复观察或重复点击次数、审批次数。它们是回归样本；本次实现不包含针对税务网站的专门操作规则。

## 验证边界

交付前会验证源代码、合成网页执行、权限与记录链路、两端安装包资源，以及 Mac 签名和公证。实际网站、安装升级、浏览器系统权限提示和 Windows 虚拟机运行由用户验收。没有把旧版本的 GUI 结果当作新包结果。
