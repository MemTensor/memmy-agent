实现和证据边界
Mac：仅在授权连接的临时微信副本内捕获；保留 CommonCrypto，并支持经本机微信 4.1.15 arm64 静态核实的 WCDB 结构和固定 XOR 常量。
所有候选密钥必须逐页通过 HMAC；全部编号消息分库验证后还必须通过正式 reader baseline，才能报告连接成功。
已验证的账号 password 才会尝试其他分库的独立 salt。raw key 不被当成账号 password。
Mac 多账号不按修改时间猜选；多个原账号都有打开数据库证据时继续报歧义。
Windows：保留已有配置和 raw literal 扫描方式；使用 Known Folders、配置中的自定义路径及进程密钥证据选择账号。
Windows reader 继续使用现有系统 bcrypt 页解密和内嵌 Python SQLite，不引入第三方 wx_key.dll。
Windows reader 的解密副本和 SQLite sidecar 统一放在该次读取的私有临时目录，初始化失败、Python SystemExit 或关闭失败均执行清理；重复关闭不再持有旧路径。
History 写入后确认游标的接口未改变；重新连接保留已经确认的游标。
普通用户走随包 Python 和预编译 helper。源码测试所用 Xcode/SQLCipher fixture 不属于新增用户依赖。
