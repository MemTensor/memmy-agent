# Memmy Computer Use 权限引导：Mac 实机验收

2026-09-28，在已解锁的 Mac 上，用当前权限引导源码和最终签名包内的原生 helper
运行隔离 Electron 面板。测试入口仅模拟缺少辅助功能权限；没有修改系统权限或用户数据。

- 原生 `settings-window --watch` 对系统设置窗口的移动输出连续边界帧；居中后的
  稳定帧为 `x=395, y=114, width=723, height=721`（逻辑点）。
- 面板实际窗口为 `545×114` 逻辑点。系统设置处于上述位置时面板为
  `(567, 714, 545, 114)`；系统设置移动时，面板更新到包括
  `(656, 599, 545, 114)` 的相应位置，移回后恢复 `(567, 714, 545, 114)`。
- 面板 AX 树显示标题、返回按钮及可用的“拖动 Memmy Computer Use 到系统权限列表”
  入口。单独验证了 preload 的状态订阅；图标加载完成后拖动入口从禁用变为可用。
- 窗口浮在系统设置上时不会因追踪更新而强制激活主 Memmy 窗口。返回到面板会
  触发 `returned` 状态更新。
- 最终签名包内同一个 `MemmyComputerUse` 的 `__memmy-history --permissions` 只读
  调用返回 `accessibility=true`、`inputMonitoring=true`、`screenRecording=true`。
  这验证了 History 在该安装路径读取同一 helper 的运行态；没有启动事件录制。

边界：没有把 helper 拖进系统列表，因为那会改变 TCC 授权；原生文件拖动的系统
落点仍需在用户主动授权的首次使用场景签收。隔离入口已退出并清理；没有在最终
签名包安装路径上触发真实的缺权限流程。这项验收证明了当前面板源码的窗口跟随，
不能替代最终安装包的整条 Agent → 工具 → PiP 验收。
